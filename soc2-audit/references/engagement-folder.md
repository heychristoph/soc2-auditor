# The engagement folder

One folder per client engagement. Every step reads and writes files here, so any step can be rerun or resumed, by any agent. JSON Schemas for each file are in `assets/schemas/`.

## Contents
- Layout
- engagement.yaml
- bundle/ (written by the connector)
- testplan.csv
- workpapers/
- opinion.json, review/, report/

## Layout

```
<engagement>/
├── engagement.yaml        scope and settings (you or the user)
├── system.yaml            optional: management's description, overrides bundle/system.yaml
├── bundle/                evidence, written once by `ingest`, then read-only
│   ├── manifest.json      every artifact: id, path, sha256, kind, controls, date, obtained
│   ├── controls.csv       the service organization's control matrix
│   ├── system.yaml        system description inputs as pulled from the source
│   ├── populations/*.csv  hires, terminations, changes, incidents ... (id, date, ...)
│   └── evidence/          files, prefixed with their artifact ID
├── testplan.csv           frequency, nature and population per control (auditor)
├── workpapers/<id>.json   one per control (tester)
├── opinion.json           the opinion decision
├── review/                coverage.md, requests.csv, rollup.md, qa.json, packet.md
└── report/                PDF, workpapers.xlsx, evidence-index.csv, report-data.json
```

## engagement.yaml

```yaml
schema_version: 1
service_organization: Northwind Analytics, Inc.   # legal name, as printed
system: Northwind Insights Platform
service_auditor: AI Audit                          # always this; the model name is in signoff
auditor_location: ""
report_type: 2                                    # 1 or 2
period: {start: 2026-01-01, end: 2026-06-30}     # Type 2
# as_of: 2026-06-30                               # Type 1 instead of period
categories: [security, availability, confidentiality]   # security is always included
subservice_organizations:
  - {name: Amazon Web Services, services: Cloud hosting, method: carve-out}
source:
  connector: probo                                # folder | probo | vanta | drata
  options: {organization_id: "..."}               # connector-specific, never secrets
management:                                       # real person and role, from the evidence
  name: Ada Lovelace
  title: Chief Executive Officer
sampling_seed: 483920117                          # set by init; never change after sampling
signoff: null                                     # written only by `signoff --model`; prints the model name, title AI Auditor, and the date
```

Secrets (API tokens) go in environment variables, never in this file.

## bundle/

**manifest.json** lists every artifact. The fields that matter when testing:

| Field | Meaning |
|---|---|
| `id` | `EV-0001` for evidence and policies, `PO-<name>` for populations, `SY-...` for the control matrix and description |
| `path` | file location relative to `bundle/` |
| `kind` | `evidence`, `policy`, `population`, `controls`, `system` |
| `controls` | control IDs the source linked this artifact to (a hint, not a limit) |
| `date` | the date the artifact refers to, when the source knows it |
| `obtained` | `direct` (pulled from the system of record) or `client` (provided by the service organization); direct evidence is more reliable |

**controls.csv** columns: `id, title, description, criteria, owner, frequency, nature, population, source_ref`. `criteria` is a space-separated list such as `CC6.2 CC6.3`.

**system.yaml** holds management's description of the system:

```yaml
status: draft | management-approved
overview: ...            # company and business
services: ...            # services in scope
commitments: [...]       # principal service commitments and system requirements
components: {infrastructure: ..., software: ..., people: ..., procedures: ..., data: ...}
boundaries: ...
subservice_organizations: [{name: ..., services: ..., csocs: [...]}]
cuecs: [...]             # complementary user entity controls
incidents: ...           # significant incidents in the period
changes: ...             # significant changes in the period
```

**populations/*.csv** always start with `id,date`; other columns vary by source.

## testplan.csv

`control_id, frequency, nature, population, sample_size, notes`. See [planning.md](planning.md).

## workpapers/<control>.json

Created by `sample` with the `plan` block filled in and `conclusion: pending`. The tester fills in everything else. See [control-testing.md](control-testing.md) for each field and `assets/schemas/workpaper.schema.json` for the exact shape.

## opinion.json, review/, report/

- `opinion.json`: see [evaluating.md](evaluating.md).
- `review/qa.json`: written by `soc2.py qa`, never by hand.
- `review/packet.md`, `report/*`: generated by `packet` and `render`.
